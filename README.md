##  Методология

### 1. Применение наценки (дерево приоритетов)

Для каждой позиции правило наценки ищется сверху вниз, берётся **первое активное** на дату `2025-10-01`:

1. **Продукт** — совпадение по коду товара
2. **Бренд / Категория1**
3. **Бренд**
4. **Сегмент / Категория1**
5. **Сегмент**

Правило считается **активным**, если одновременно:
- `Активный = Да`
- `Дата начала ≤ сегодня`
- `Дата окончания` пуста или `≥ сегодня`

### 2. Универсальная формула наценки

В справочнике используются две шкалы записи:

```python
def apply_markup(zakupka, nacenka):
    if nacenka >= 1:
        return zakupka * nacenka          # множитель (Clarins: 1.03 → ×1.03)
    else:
        return zakupka * (1 + nacenka)    # процент (Vivienne Sabo: 0.59 → ×1.59)
```

### 3. Индекс цен

Для каждого конкурента:

```
Индекс = Наша цена / Цена конкурента × 100%
```

- `100%` — паритет
- `> 100%` — мы дороже
- `< 100%` — мы дешевле

Пропуски (`NaN`) у конкурентов игнорируются.

### 4. Рекомендации по скидке

- Минимальная цена с маржой 10% (маржа от цены продажи):
  ```
  мин_цена = закупка / 0.9
  ```
- Целевая цена = минимальная цена рынка × 0.99.
- Если `целевая_цена ≥ мин_цена` → можно снижать, считаем размер скидки.
- Иначе → снижение уводит маржу ниже 10%, нужно менять справочник наценок.

5. **Рекомендации — гипотезы.** Перед внедрением требуется проверить эластичность спроса и реакцию конкурентов.

##  Задача 2. Эластичность спроса и рекомендации по скидкам

###  Цель

На основе статистики цен и объёма продаж по 10 SKU за период июнь–сентябрь 2024 определить размер скидки, при которой продажи каждой позиции вырастут в 2 раза.

###  Методология

1. **Разметка дней.** Каждый день отнесён к группе «со скидкой» или «без скидки» в зависимости от того, совпадает ли `Цена с учётом скидки` с `Розничной ценой`.

2. **Средние продажи.** Для каждого товара посчитаны средние продажи в дни со скидкой и без неё.

3. **Эластичность спроса.** Рассчитана как отношение процентного роста продаж к проценту скидки:

   ```
   Эластичность = (% роста продаж) / (% снижения цены)
   ```

4. **Скидка для удвоения продаж.** При линейном приближении:

   ```
   Нужная скидка, % = 100 / Эластичность
   ```

   То есть снижение цены на эту величину даст рост продаж в 2 раза.

###  Итоговое предложение

**Средняя рекомендуемая скидка для удвоения продаж — 19%.**

- Для **эластичных товаров** (эластичность > 6) скидка **15–17%** — оптимальный минимум, максимальный эффект при минимальной потере маржи.
- Для **умеренно эластичных** (5–6) скидка **17–20%**.
- Для **слабых** (эластичность < 4.5) скидка **24–26%** — только при подтверждённой рентабельности.

###  Ограничения и допущения

1. **Сезонность.** Скидки в данных приходятся в том числе на август–сентябрь (низкий сезон). Это может искажать эластичность — часть роста продаж может быть связана с промо, часть — с сезонностью.
2. **Линейная экстраполяция.** Формула `Скидка = 100 / Эластичность` предполагает линейную зависимость. В реальности при больших скидках (25%+) спрос начинает насыщаться, и эффект падает.
3. **Маржа не учитывается** в этой задаче — только рост продаж. Для внедрения нужно проверить, что скидка не уводит маржинальность ниже 10% (см. задачу 1).
4. **Ограниченная выборка.** Анализ проведён по 10 SKU. Для полного портфеля требуются более широкие данные и, желательно, A/B-тестирование.

## Задача 1. Сводная информация по товарам

Для каждого товара с продажами за последний полный месяц вывести:
- код товара, название, бренд, категорию,
- сумму продаж в шт и руб за последний месяц,
- среднюю цену за последний месяц,
- средний объём продаж за 3 месяца,
- разницу между текущим остатком и средним объёмом продаж.

### SQL (ClickHouse)

```sql
WITH
    toStartOfMonth(today() - INTERVAL 1 MONTH) AS last_month_start,
    toStartOfMonth(today()) - INTERVAL 1 DAY   AS last_month_end,
    toStartOfMonth(today() - INTERVAL 3 MONTH) AS three_month_start
SELECT
    p.itemid,
    p.name_ax,
    p.brand_name_ax,
    p.category,
    sum(s.qty)                        AS sales_qty_month,
    sum(s.qty * s.price)              AS sales_rub_month,
    sum(s.qty * s.price) / sum(s.qty) AS avg_price_month,
    m3.avg_qty_3m,
    st.stock_current - m3.avg_qty_3m  AS stock_diff
FROM dwh.sales AS s
INNER JOIN dwh.products AS p ON p.itemid = s.itemid
LEFT JOIN (
    SELECT itemid, qty AS stock_current
    FROM dwh.stock
    WHERE date = (SELECT max(date) FROM dwh.stock)
) AS st ON st.itemid = s.itemid
LEFT JOIN (
    SELECT itemid, sum(qty) / 3 AS avg_qty_3m
    FROM dwh.sales
    WHERE date >= toStartOfMonth(today() - INTERVAL 3 MONTH)
      AND date <  toStartOfMonth(today())
    GROUP BY itemid
) AS m3 ON m3.itemid = s.itemid
WHERE s.date >= last_month_start
  AND s.date <= last_month_end
GROUP BY p.itemid, p.name_ax, p.brand_name_ax, p.category,
         m3.avg_qty_3m, st.stock_current
HAVING sum(s.qty) > 0
ORDER BY sales_rub_month DESC;
```

**Пояснения:**
- Границы месяца определяются **функциями ClickHouse** (`toStartOfMonth`, `INTERVAL`), а не хардкодом.
- Средняя цена — **средневзвешенная** `SUM(qty*price)/SUM(qty)`.
- Средний объём за 3 месяца — `SUM(qty)/3`.
- Текущий остаток — `qty` на последнюю дату в `dwh.stock`.
- `HAVING sum(s.qty) > 0` — оставляем только товары с продажами за последний месяц.

## Задача 2. Топ-5 брендов по выручке с сравнением

Вывести топ-5 брендов по выручке за последний полный месяц с сравнением с предыдущим.

### SQL (ClickHouse)

```sql
WITH
    toStartOfMonth(today() - INTERVAL 1 MONTH) AS last_month_start,
    toStartOfMonth(today()) - INTERVAL 1 DAY   AS last_month_end,
    toStartOfMonth(today() - INTERVAL 2 MONTH) AS prev_month_start,
    toStartOfMonth(today() - INTERVAL 1 MONTH) - INTERVAL 1 DAY AS prev_month_end
SELECT
    p.brand_name_ax AS brand_name_ax,
    sumIf(s.qty * s.price,
          s.date >= last_month_start AND s.date <= last_month_end) AS revenue_last_month,
    sumIf(s.qty * s.price,
          s.date >= prev_month_start AND s.date <= prev_month_end) AS revenue_prev_month,
    revenue_last_month - revenue_prev_month AS delta_rub,
    round((revenue_last_month - revenue_prev_month) / revenue_prev_month * 100, 1) AS delta_pct
FROM dwh.sales AS s
INNER JOIN dwh.products AS p ON p.itemid = s.itemid
WHERE s.date >= prev_month_start
  AND s.date <= last_month_end
GROUP BY p.brand_name_ax
HAVING revenue_last_month > 0
ORDER BY revenue_last_month DESC
LIMIT 5;
```
Задание 5: Расчет WAU скользящим окном в ClickHouse

Данный проект содержит SQL-решение для расчета метрики **WAU (Weekly Active Users)** с использованием скользящего окна в СУБД **ClickHouse**.

##  Условие задачи

Необходимо рассчитать **WAU** (количество активных пользователей сайта) скользящим окном в **7 дней** с шагом в **1 день**. При этом текущая дата должна включаться в расчет.

**Пример расчета:**
*   Для даты `19.12.2023` — WAU рассчитывается за период `13.12.2023 – 19.12.2023`.
*   Для даты `20.12.2023` — WAU рассчитывается за период `14.12.2023 – 20.12.2023`.
*   Для даты `21.12.2023` — WAU рассчитывается за период `15.12.2023 – 21.12.2023`.
*   И так далее.

##  Исходные данные

### Таблица `dwh.site_activity` — Активность пользователей на сайте

| Столбец | Описание |
| :--- | :--- |
| `action_id` | id события |
| `timestamp` | время события |
| `user_id` | id пользователя |
| `action` | совершенное действие |
| `item_url` | страница товара, на котором было совершено действие |

##  Логика решения

Для корректного расчета скользящего окна в ClickHouse используется подход с **размножением событий** через `arrayJoin()` и `range()`.

**Алгоритм:**
1.  **Размножение событий:** Каждое событие пользователя "размножается" на 7 дат: саму дату события и 6 последующих дней. 
    *   *Пример:* Если пользователь был активен `13.12.2023`, то в развернутом виде он появится в строках за `13, 14, 15, 16, 17, 18, 19` декабря.
2.  **Группировка:** Все размноженные события группируются по дате (`activity_date`).
3.  **Подсчет уникальных пользователей:** Для каждой даты считается `uniq(user_id)`.
    *   *Результат:* Для даты `19.12.2023` в группу попадут все уникальные пользователи, у которых были действия с `13` по `19` декабря. Это и есть искомое скользящее окно.

Такой подход является оптимальным для ClickHouse, так как позволяет эффективно распараллелить вычисления на больших объемах данных.

##  SQL-запрос

```sql
WITH 
    -- Определяем границы интересующего периода (например, последние 30 дней)
    toDate(now()) - INTERVAL 30 DAY AS start_date,
    toDate(now()) AS end_date
SELECT 
    -- Дата, на которую рассчитывается WAU
    activity_date AS "Дата расчета",
    
    -- Количество уникальных пользователей за 7 дней (включая текущую дату)
    uniq(user_id) AS "WAU"
FROM (
    -- Шаг 1: Размножаем каждое событие на 7 дат (само событие и 6 последующих дней)
    SELECT 
        user_id,
        arrayJoin(
            arrayMap(
                x -> toDate(timestamp) + x, 
                range(0, 7)
            )
        ) AS activity_date
    FROM dwh.site_activity
    -- Фильтруем исходные данные, чтобы не размножать лишние события
    WHERE toDate(timestamp) >= start_date - INTERVAL 6 DAY 
      AND toDate(timestamp) <= end_date
) AS expanded_activity
-- Шаг 2: Фильтруем только те даты, которые нам нужны для отчета
WHERE activity_date >= start_date AND activity_date <= end_date
-- Шаг 3: Группируем по дате расчета и считаем уникальных пользователей
GROUP BY activity_date
